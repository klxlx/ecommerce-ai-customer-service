# 上下文工程实现说明

状态：Phase 1 已实现  
基线：`dfc0b0f`  
分支：`feat/context-pack`

## 1. 目标与边界

本次只解决“模型每轮看到什么”，不引入长期记忆。

已实现：

- 统一 Context Pack：System、当前槽位、最近 6 轮历史、结构化工具事实、当前问题。
- 字符预算与截断顺序。
- 槽位白名单，避免内部字段进入 Prompt。
- 订单/商品/售后/知识工具事实格式化，禁止原始 JSON 进入回答 Prompt。
- `AgentRun.trace.context` 记录上下文清单。

未实现：

- L2 摘要、L3 用户画像、跨会话记忆。
- LangGraph Checkpointer、任务断点恢复。
- 数据库迁移。
- 节点级耗时与精确故障定位。

## 2. 目录

```text
app/context/
├── __init__.py
├── builder.py       # 五块上下文组装与总预算
├── budget.py        # 轮数窗口、字符截断、正数配置兜底
├── formatters.py    # 槽位与工具事实格式化
└── models.py        # ContextPack / ContextManifest
```

Prompt 接入位置：

- `app/prompts/answer.py`：知识回答、订单回答。
- `app/prompts/router.py`：意图路由。
- `app/prompts/tool_planner.py`：订单只读 Function Calling 规划。
- `app/prompts/chitchat.py`：闲聊中的天气工具事实。
- `app/graph/nodes.py`：根据开关选择新 Context Pack 或旧 Prompt 路径。

## 3. Prompt 组装顺序

```text
System Prompt
→ 当前会话槽位
→ 当前工具事实
→ 知识缺口协议等固定后缀
→ 最近 6 轮历史
→ 当前用户输入
```

事实优先级写死在回答 Prompt 中：

```text
安全规则
> 当前工具事实
> 当前用户明确输入
> 当前会话槽位
> 最近历史
```

历史只用于理解指代，不能覆盖当前工具事实。

## 4. 预算

| 配置 | 默认 | 作用 |
|---|---:|---|
| `CONTEXT_ENGINE_ENABLED` | `0` | 总开关，关闭时完全走旧 Prompt |
| `CONTEXT_MAX_CHARS` | `6000` | 单次 Prompt 总字符预算 |
| `CONTEXT_HISTORY_TURNS` | `6` | 最近用户轮数 |
| `CONTEXT_HISTORY_MAX_CHARS` | `3000` | 历史字符预算 |
| `CONTEXT_TOOL_FACTS_MAX_CHARS` | `1200` | 工具事实字符预算 |
| `CONTEXT_SLOTS_MAX_CHARS` | `300` | 槽位字符预算 |

截断顺序：

1. 先丢最旧历史；丢弃后如果首条是 assistant，也一并丢掉。
2. 工具事实按自身预算截断。
3. System 与当前用户输入不截断。
4. 超总预算时 `manifest.truncated=true`，便于排查。

## 5. 工具事实格式

原始 JSON 不再进入回答 Prompt。示例：

```text
订单 1 笔：
1. ORD-1001：状态「已发货」；金额 ¥99.00 元；下单时间 2026-08-01 10:00；
商品：测试商品A、测试商品B x2；最新物流：运输中（上海）已发出
```

支持的 section：

- `orders` / `order`
- `product`
- `after_sale`
- `knowledge`
- `weather`

未知 section 不直接拼接，记录到 `manifest.ignored_tool_sections`。新增工具时必须补对应 formatter，避免静默丢事实。

## 6. 槽位白名单

只允许以下字段进入 Prompt：

- `order_no`
- `query_scope`
- `product`
- `refund_amount`
- `after_sale_action`
- `pending_intent`
- `missing_slot`

`pending_slots`、`last_handoff`、内部 ID 等不进入 Prompt，避免跨轮串单或泄漏内部状态。

## 7. trace 记录

`AgentRun.trace.context` 示例：

```json
{
  "purpose": "order_answer",
  "base_chars": 1350,
  "slots_chars": 20,
  "tool_facts_chars": 180,
  "history_chars": 420,
  "user_chars": 7,
  "total_chars": 1977,
  "history_turns": 6,
  "history_messages": 12,
  "history_messages_dropped": 2,
  "slots_included": ["order_no", "query_scope"],
  "tool_sections": ["orders"],
  "ignored_tool_sections": [],
  "truncated": false

```

只记录计数和键名，不落库 Prompt 原文或用户消息正文。

## 8. 固定样例实测

固定构造 8 轮订单对话、1 笔订单、旧版 JSON 工具结果：

| 指标 | 旧 Prompt | Context Pack |
|---|---:|---:|
| Prompt 字符数 | 1023 | 918 |
| 历史消息数 | 6 | 12 |
| 组装平均耗时 | — | 0.029 ms/次 |

结论：历史窗口翻倍的情况下，Prompt 仍缩小 10.3%。这是固定样例结果，不代表所有业务场景的普遍降幅。

## 10. 回滚

设置：

```env
CONTEXT_ENGINE_ENABLED=0
```

即恢复旧 Prompt 行为，不需要回滚代码或数据库。Context Pack 相关代码仍保留，但不会进入执行路径。
