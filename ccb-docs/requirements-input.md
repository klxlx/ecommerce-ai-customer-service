项目目标：
开发一套可落地演示的电商场景智能客服系统，以「静态知识检索 + 动态数据查询」双引擎为核心，采用父子块分层 RAG 架构保障回答准确性与上下文完整性，基于 LangGraph 实现全链路智能编排；覆盖商品咨询、交易规则查询、订单进度查询三大核心业务，支持多轮对话记忆、闲聊管控与人工兜底，可用于项目演示、课程设计与能力验证。
使用者和场景：
终端使用者：电商消费者 / 模拟测试用户
核心使用场景： 
  商品咨询：查询商品参数、使用方法、注意事项、保修政策，对比商品差异
  规则咨询：查询退换货政策、售后流程、运费规则、纠纷处理方式等平台交易规则
  订单查询：查询订单状态、物流进度、价格库存等实时业务数据
  闲聊引导：日常寒暄后自然引导至业务咨询，控制无效闲聊轮次
  招呼寒暄：检测打招呼/寒暄吗，固定回复防止浪费资源浪费
  人工转接：超出能力范围时平滑转接人工，同步用户核心诉求

必需功能：
父子块分层 RAG 检索：商品、交易规则双知识库，子块做向量召回、父块提供完整上下文，搭配重排精筛，支持答案来源溯源
实时业务数据查询：商品价格库存、订单状态物流等动态数据直连关系型数据库，通过工具调用获取，绝不入库向量库
LangGraph 智能体编排：统一入口意图识别，自动分流知识检索 / 数据查询 / 闲聊 / 转人工，自然语言重组，支持多轮上下文记忆、缺失信息主动补全、闲聊轮次管控，
全量数据持久化：知识库父块、商品订单数据、会话消息全量入库，支持历史回溯与效果优化
技术要求：
  核心技术栈：Python 3.14、LangChain、LangGraph、PostgreSQL 15+ + PGVector、FastAPI、
  模型层：兼容 OpenAI 协议的对话大模型；阿里云text-embedding-v3 嵌入模型；text-rerank-v1 重排模型
  部署要求：支持 Docker Compose 一键部署，本地环境可直接运行
  架构要求：分层解耦，数据层、检索层、编排层、服务层独立模块化
  安全要求：订单查询严格校验用户权限，禁止越权访问

禁止事项：
禁止将商品价格、库存、订单状态等动态数据写入向量知识库，避免数据过期产生幻觉
禁止引入未约定的重型第三方依赖，保持项目轻量化可运行
禁止修改父子块核心关联逻辑（parent_id 绑定、子块召回父块补全）
禁止实现业务写入操作（如修改订单、同意退款），仅保留查询与指引能力
禁止使用无版权授权的商用素材，知识库素材限公开合规资料与自制模拟数据
